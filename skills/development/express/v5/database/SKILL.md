# Database & Models

## Trigger
Use this when adding/updating database models, schema rules, migrations, or query patterns in services.

## Best Practices

### General
- Keep model definitions and data operations decoupled from controller logic.
- Keep database operations strictly within the service layer; controllers never query the DB directly.
- Apply write operations inside transactions when consistency is critical across multiple entities.
- Validate payload structures at the route boundary (e.g., via Zod middleware) before passing them to the database layer.

### Mongoose / MongoDB Stack
- Keep model definitions explicit and strongly typed.
- Define indexes and unique constraints in schemas, not ad-hoc in service code.
- Use `.lean()` or specific projections for read-heavy operations.
- Centralize connection management in `src/config/db.ts`.

### Prisma / PostgreSQL Stack
- Manage database connections via a client singleton (e.g., `src/common/utils/prismaClient.ts`) to avoid leaking connection pools in serverless/hot-reload environments.
- Colocate `<feature>.model.ts` to export types generated by the Prisma client.
- Run migrations using standard CLI workflows (`prisma migrate dev`).

## Reusable Blueprints

### Prisma Service Blueprint
```ts
import { prisma } from '../../common/utils/prismaClient.js';
import { AppError } from '../../common/utils/AppError.js';

export const myService = {
  findById: async (id: string) => {
    const record = await prisma.myModel.findUnique({
      where: { id },
    });

    if (!record) {
      throw new AppError(404, 'Record not found');
    }

    return record;
  },
};
```

### Mongoose Service Blueprint
```ts
import { MyModel } from './my.model.js';
import { AppError } from '../../common/utils/AppError.js';

export const myService = {
  findById: async (id: string) => {
    const record = await MyModel.findById(id).lean();

    if (!record) {
      throw new AppError(404, 'Record not found');
    }

    return record;
  },
};
```

## Avoid
- Unbounded queries without pagination.
- Silent schema drift by using loosely typed fields.
- Query composition directly inside controllers.
